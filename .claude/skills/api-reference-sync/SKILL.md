# api-reference-sync

`/docs` is generated, not hand-written. `src/content/api.json` is produced from the C# source by
`SceneBuilder.DocGen` in the CodeScenesUnity repo and committed here; every page, anchor, signature,
and the text mirror derive from it.

Nothing in this repo is edited to document a new type or member. Change the C# source, regenerate,
verify, deploy.

## The XML doc comments are published copy

`///` blocks on `com.codescenes/Runtime/*.cs` are read by users on the website, not just by the IDE.
Write them as reference documentation. Internal contracts, spec numbers, task ids, and pointers into
`SceneBuilder.Core` internals do not belong there.

`<see cref="..."/>` resolves three ways: to an in-site link when it names something in the authoring
surface, to `docs.unity3d.com/ScriptReference/<Name>.html` when it names a Unity type, and to plain
code otherwise. An unqualified cref resolves against the type the comment sits on, so
`<see cref="Evaluate"/>` inside `FitSize` links to `FitSize#evaluate`.

## Step 1 — CodeScenesUnity

Edit the source: doc comments and public members in `com.codescenes/Runtime/`, or the SB#### table in
`CodeScenes.Analyzers/DiagnosticDescriptors.cs`.

Run that repo's gate and quote the verdict line:

```bash
cd ../CodeScenesUnity
./verify.sh
```

Read the `GATE PASS` / `GATE FAIL` line, never an exit code alone. A change under `com.codescenes/`
puts the multi-minute Unity EditMode suite in scope, so do not have the `unity-gate/` project open in
an interactive editor while it runs (Unity holds a single-instance lock).

Commit and push there before regenerating here, so the committed `api.json` corresponds to a pushed
commit.

## Step 2 — regenerate here

```bash
npm run api:sync
```

Runs `SceneBuilder.DocGen` against `../CodeScenesUnity` and rewrites `src/content/api.json`, then
regenerates the text mirror. Point it elsewhere with `CODESCENES_UNITY=/path/to/repo npm run api:sync`.

It prints what it found, for example `13 types, 52 members, 11 diagnostics`. Check that count against
what you expect before continuing; a member silently missing here is a member missing from the site.

## Step 3 — build and verify

```bash
npm run build
python3 -m http.server 4321 --directory out &
node scripts/verify-docs.mjs
```

`verify-docs.mjs` drives the exported site in Chromium and asserts every member anchor exists, cross
-type links navigate and land below the fixed header, no page scrolls sideways at 1440px or 390px,
the mobile nav collapses, and both mirror files are served. It ends with `DOCS PASS` or `DOCS FAIL`.

Set `SHOT_DIR=/some/dir` to also write screenshots. Look at them; the suite cannot see ugly.

Serve with `python3 -m http.server`, not `npx serve -s out`. The `-s` flag is SPA mode and rewrites
every route to the home page, which makes all 13 type pages look identical and pass a naive check.

## Step 4 — commit

Tracked: `src/content/api.json`, and any site code you changed.

Not tracked, regenerated by `prebuild` on every build: `public/docs/api.md`, `public/llms.txt`. Do not
add them.

## Step 5 — deploy

```bash
npm run build
npx firebase deploy --only hosting
```

Then confirm on the live domain, not just locally:

```bash
for p in /docs/ /docs/api/node-handle/ /docs/diagnostics/ /docs/api.md /llms.txt; do
  printf "%-28s %s\n" "$p" "$(curl -s -o /dev/null -w '%{http_code}' https://codescenes.dev$p)"
done
```

## What happens automatically

- **A new type** gets its own page and sidebar entry. `generateStaticParams` reads `api.json`; there is
  no route to add.
- **A new overload** joins the existing member section under the same anchor.
- **A new diagnostic** appears on `/docs/diagnostics/` grouped under its category.
- **A new diagnostic category** renders without an intro paragraph until you add one to
  `CATEGORY_BLURB` in `src/app/docs/diagnostics/page.tsx`.

The only hand-written copy in the whole reference is that map plus the page intros in
`src/app/docs/page.tsx` and `src/app/docs/diagnostics/page.tsx`. Everything else comes from the C#.

## What breaks links

URLs come from the C# names. Renaming a type or a member changes its URL or anchor and breaks any
external link to it.

- Type slug: kebab-cased name, with an arity suffix when generic. `ComponentHandle<T>` is
  `component-handle-1`; `InstanceHandle` and `InstanceHandle<TRef>` are `instance-handle` and
  `instance-handle-1`.
- Member anchor: kebab-cased name, shared by all overloads. Adding or reordering an overload is safe.

## Diagnostics extraction is positional

`DiagnosticExtractor` reads `new DiagnosticDescriptor(...)` arguments by position: id, title,
messageFormat, category, severity. Two ways that degrades quietly:

- Fewer than five arguments and the descriptor is skipped entirely. Check the count printed in step 2.
- A slot holding anything other than a string literal or a `const` declared in the same class comes
  through empty. The id falls back to the field name; title, message, and category render blank.

Because the read is positional, reordering the arguments mislabels the entry rather than failing.

A `messageFormat` that is only placeholders (`"{0}"`) carries no information without its runtime
arguments, so the site omits it rather than printing `{0}`.

## Files

| Path | Role |
| --- | --- |
| `../CodeScenesUnity/SceneBuilder.DocGen/` | The generator. Syntax-only Roslyn, no Unity DLLs, no project load. |
| `src/content/api.json` | Generated, committed. The single input to every docs page. |
| `src/lib/api.ts` | Types over `api.json` plus slug, outline, and clipping helpers. |
| `src/app/docs/` | Routes: overview, `api/[type]`, `diagnostics`. |
| `src/components/docs/` | `DocProse` (doc runs to JSX), `Signature` (shiki), `DocsSidebar`, `OnThisPage`. |
| `scripts/gen-api-mirror.mjs` | Writes `public/docs/api.md` and `public/llms.txt`. Runs from `prebuild`. |
| `scripts/verify-docs.mjs` | The browser check. |

## Outstanding

Five doc comments read as internal notes and are currently published: the `FitSize` and `SurfaceSnap`
type remarks (both name `SceneBuilder.Core.Model.SpatialComponents.*Fields`), and the `ResetBaseline`
summaries on both (NaN sentinel, `PlanExecutor`). Fix them in the C# source, not here.

`FitSize` and `SurfaceSnap` also publish `Evaluate`, `ResetBaseline`, `mode`, `value`, and `size`
because Unity serialization needs them public. If they are not meant to be user-facing API, the
generator needs an exclusion rule.
